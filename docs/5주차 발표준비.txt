> 슬라이드 4: 중심식을 띄워놓고 간단한 설명, 각 항별로 한 실험의 이름과 대표 이미지를 첨부함.
중심식은 deferred + prepass 와 비교한 결과를 기준으로 함.
각 항별로 실험의 상태 (전주에 실행 / 이번주에 실행 / 고도화 단계에서 실행 / 범위 밖) 표기

여기서 장점 항은 다 측정했고
단점 항은 아래에서 측정할 것임.
마치 렌더링 논문에서 rendering equation 쓰듯이 쓰면 됨.

nanite에서는 ~ doom에서는 ~ horizon에서는 ~ 이런 목적으로 사용했습니다.

이 프로젝트는 visibiltiy buffer 의 성능적인 특성을 분석하고 다른 기법과 비교해 유불리한 지점을 실험적으로 탐색,
해당 기법의 적용 시에 유의미하게 고려할 수 있는 결론을 만들어내고자 하는 취지를 가지고 있습니다.
파트는 실험과 고도화 두 부분으로 나눠집니다. 실험은 인공 씬과 실제 씬을 모두 사용, 렌더러는 점차 발전시키며
donut의 deferred lighting / tome mapping 셰이더를 그대로 가져오고 버퍼나 상수는 가장 영향이 적은 값을 사용하는 형태로 진행합니다.
비교 알고리즘은 forward (+prepass), deferred (+prepass), visbuf (+gbuffer) 의 여섯 개이고,
추가로 debug view / frame statistics / visbuf view 용 렌더러가 있으며
카메라 녹화/보간/재생, timestamp query readback, csv write 등의 기능을 사용해 측정하고 기록합니다.

> 이거 그냥 넘어가자 다 아는거니까

visbuf가 이득을 볼 수 있는 세 지점에 대한 실험을 인공 씬을 사용해 전 주차에 진행했고, ~한 결론이 나왔습니다.
(geometry 처리, overdraw, quad 에 관한 전 주차 실험 내용 요약)
이를 통해 성능 모델을 세우고 검증할 수 있었습니다.

gbuffer의 경우 많은 상황에서 gbuffer가 필요하고, gbuffer를 구성하지 않을 경우 렌더러의 다른 부분이 visbuf에 많은 영향을 받으므로
gbuffer는 구성한다고 가정했습니다. 따라서 이후 고도화엔 gbuffer를 구축하며 deferred와 비교하게 됩니다.
(하지만 논문에서는 gbuffer를 오늘 실험을 진행해 나온 부분을 발표 - 이거 하자 이미 알고리즘 다 구성돼서 실험만 하면 된다
	-> gbuffer 대역폭으로 인한 장점도 이번 주차에 실험을 진행해, 이번 주 첫 번쨰 활동으로 후술하겠습니다)


반만 주 단점으로는 indirect access 증가와 barycentric/derivative 복원 비용, material 관련 스케줄링 비용,
알파 테스팅/모션벡터 문제 등이 있습니다.

barycentric/derivative 복원 비용의 상한은 씬 지오메트리의 월드 공간 복잡도에 무관하다고 판단해
하나의 구현을 만든 후 이번 주 측정/검증만 거쳤습니다.
이후 jungle에서도 개선을 할 수 있기 때문입니다.
이는 이번 주 두 번째 활동으로 후술합니다.

 material역시 PSO의 개수를 제외하면 씬 지오메트리의 월드 공간 복잡도와 무관하다고 판단해
하나의 구현을 한 후 측정/검증을 진행했습니다.
이후 jungle에서도 개선을 할 수 있기 때문입니다.
다만 PSO 수나 material 분포의 locality와의 연관성이 있기에 이번 주 실험을 진행했습니다.
이는 이번 주 세 번쨰 활동으로 후술합니다.

indirect access는 (가능하면 간단한 실험 진행)
-> 넘어감.
넘어간 이유: 나중에 HW counter로 다룰 수 있어서. (영향을 받는 게 명확하고 나중에도 관측 가능하므로)

기타 alpha test / motion vector / MSAA 등에서 일어나는 문제는 추후 고도화와 함께 진행할 예정입니다.
